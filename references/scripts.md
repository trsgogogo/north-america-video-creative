# Scripts and channel deliverables

## Four formats from the source documents

If asked for a hook → four scripts, create four complete versions below, each with hook, buyer friction, mechanism/product role, evidence or demonstration, reason for the next action, and one CTA. Include discounts and aftersales only if verified. Missing proof belongs in production notes, not fabricated narration.

For video, use a table: time range | spoken English | shot/on-screen text | evidence/production requirement. Fit the spoken word count to the duration; approximately 130–160 words/minute is a planning assumption, not a guarantee. Leave time for pauses, actions and on-screen reading. Do not promise a finished video when delivering scripts.

1. **Story / case narrative**: result or concrete obstacle → relevant buyer → 2–3 causal stages → honest outcome → product's specific role → CTA. If no actual customer story exists, use a labeled dramatization or switch to an educational script. Never invent “I made $100k” autobiographical proof.
2. **Relatable comedy**: recognizable situation → expectation → specific reversal → useful resolution → CTA. “If [industry] told the truth” must be obvious satire, not fabricated allegations about named businesses. Product solves the frustration naturally.
3. **Education**: useful payoff → specific problem → actionable steps → demonstration/check → CTA. Choose a compact tutorial, checklist, comparison, pitfalls guide, or staged explanation. Questions can organize internal reasoning while the public headline remains declarative.
4. **Process / build in public**: preview actual result or stated objective → sequential meaningful actions → obstacle/tradeoff → visible check → result and limit → CTA. Every stage adds information. Accelerated footage must not imply impossible actual completion times.

## Production handoff

For TikTok, Reels, Shorts, or a short-video ad, deliver: target viewer and scene; one core promise; duration; first frame; hook; timestamped spoken copy and shots; on-screen text; demonstration/proof; CTA; props/assets; and assumptions. Read only the applicable platform constraints when a technical delivery specification is required.

Keep narration, captions and visuals complementary. Mark footage as available, needs capture, or illustrative. Never silently assume customer footage, comparison tests, testimonials, licensed music, or a spokesperson exists. For a low-resource shoot, propose a phone/screen-recording version.

Do not attach unrelated long-form articles, landing pages or outreach sequences. A video caption or thumbnail line is appropriate when requested or necessary for the handoff. Use an available production skill/tool only for an actual requested finished-video deliverable.

## Example: B300 supply and token access

Fictional example brief: a supplier offers B300 capacity and token access, with potential volume discounts. Unknown: sale vs rental, region, exact configuration, stock quantity, provider/model rights, prices, SLA, availability dates, measured performance and offer terms. Do not collapse GPU hardware supply and API token access into an interchangeable product.

Illustrative spoken-copy seed, to be expanded into timed shots if requested:

> B300 supply and token access for teams planning their next AI workload.
>
> Send me the workload, region, timeline, and expected usage. That gives us a useful starting point for discussing fit and a quote.
>
> Volume-based discounts may be available depending on the size and terms of the request.
>
> DM me your requirements.

Humorous opening alternative: “Your AI demo works. Now comes the part where someone asks about compute.”

Internal production note: confirm transaction model and fulfillment before publishing a specific offer. A diagnostic/test request can replace a price promise. This example does not establish market demand or current stock verification.

## Example: 30-second education script (illustrative)

| Time | Spoken English | Visual | Requirement |
|---|---|---|---|
| 0–5s | Your AI demo works. Now meet procurement. | Working demo → blank supplier brief | Use actual demo or label mockup |
| 5–13s | Before asking for a GPU quote, write down the workload, the region, and when you need it. | Three fields appear | No product-performance claim |
| 13–23s | Then add expected usage and the constraints that matter: setup, support, and data handling. | Fill sample fields | Sample values labeled illustrative |
| 23–30s | Send the same brief to each supplier. Give yourself something useful to compare. | Side-by-side blank comparison | Supply the brief if promising a download |

This demonstrates educational/process writing. It is not a report of a recorded video or an executed benchmark.
